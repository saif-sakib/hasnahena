# Guardrails

The suites and CI checks here **enumerate rather than list**, and fail the build
when the code grows something they do not know about. That is deliberate — a
list a human maintains goes stale the day it is written.

[CLAUDE.md](../CLAUDE.md) carries the same 94 triggers compressed to *what fails*.
**This file is why.** Every row below keeps the full account of the defect that
put it there, because the reasoning is what stops the idea coming back. When a
guard fires and the one-line version is not enough, the row is here under the
same trigger.

Where a new test goes, and what is deliberately uncovered: [testing.md](testing.md).

A refused applicant's identity **photographs** go at the decision, not on the text's clock: an NID scan is the most damaging thing here, it is served from a URL needing no login, and nothing that justifies keeping a refusal on file needs the picture. The erasure records are permanent, circularly — a policy that expired them would destroy the proof of its own compliance |
| a **document uploaded before somebody is a member** | `apps/web/test/unit/image-uploads.test.ts` — it goes under the application, and the **approval moves it** into `people/<accountNo>` beside the avatar ([ADR-040](decisions.md)). Two meaningful folder names are still worse than one when nothing joins them: "delete everything about this member" then needs a database join, which is the thing the erasure destroys. Move with `moveAsset` (a rename — an NID scan must never be re-encoded) and clean up with `deleteEmptyFolder`, never `deleteFolder`, which would finish a half-done move by deleting the half that did not move |
| a **credential to an API response** | `apps/web/test/unit/approval-credentials.test.ts` — and ask where it will be read. Approving a registration returned the temporary password and the approvals screen printed it, because most members have no email ([ADR-036](decisions.md)) so the screen was the only delivery. An account number is a *name*; a password is a *key*, and a queue screen in a shared office is where the owner of the account is usually not standing. The member with no email gets one from `reset-password` on their own page ([ADR-042](decisions.md)). The test fails in both directions — a field returned with no screen to show it, and a screen reading a field nothing sends |
| a **list that only grows** | don't `COUNT(*)` it. `/api/v1/admin/audit-logs` ran a full scan per keystroke of the search box, against a database that bills for being awake ([ADR-035](decisions.md)), to render the word "of". Ask for `limit + 1` rows and answer `hasMore` |
| a **date field for something that happened long ago** | use `components/ui/date-of-birth-input.tsx`, not `type="date"`. The platform calendar opens on this month, so a member born in 1985 is asked to travel there — tens of taps on a low-end Android, and several vendors hide the year list behind an unlabelled caret. A calendar is the right control for dates near today and a birthday is never near today |
| a **column to `users`** | `apps/web/test/routes/identity-integrity.test.ts` — the erasure must clear it, or it must be on that test's `KEPT` list with the reason written down. "Erase everything" is a promise that decays one schema change at a time: the first version cleared the name, the NID and the address and left gender, marital status, children, language and office standing, and nothing failed |
| a **page of a list that only grows** | `apps/web/test/unit/pagination.test.ts` and the bounded count in `app/api/v1/admin/audit-logs/route.ts` — numbered pages need a total, and a plain `COUNT(*)` is a full scan per keystroke against a database that bills for being awake ([ADR-035](decisions.md)). Count to a **ceiling** instead: O(cap), not O(table), reporting "at least" when it hits one. `pageWindow` keeps the control a constant width, because a row that reflows under a thumb at 412 px is how a mis-tap happens |
| a **`Disallow` in `robots.ts`** | ask whether the page is linked. `Disallow` forbids *fetching*, so a crawler never reads a `noindex` on the same page — and `/login` and `/register` are linked from every public header, so Bing followed them, was refused, and filed "Blocked by robots.txt" against a site trying to say the opposite. `noindex` is also the stronger of the two: `Disallow` leaves a URL listable from inbound links with no description. Only what must never be *fetched* belongs there |
| a **submit handler for anything that must happen once** | `apps/web/e2e/forms.spec.ts` — guard it with a **ref, checked before the first `await`**. `disabled={isSubmitting}` is React state and the button is not disabled in the DOM until the next render, so two taps inside that window both pass; on login each mints a session and the two race to write the token. Test it with two `requestSubmit()` calls in one tick, which bypasses `disabled` entirely — a timing-based test passed in isolation and failed only in the full suite, twice, and was written off as flaky |
| **SQL inside a Go string** | `apps/api/internal/repositories/sql_schema_census_test.go` — `TestEverySQLLiteralMatchesTheSchema` parses every source, pulls each raw-string statement out and asks Postgres to `PREPARE` it. Nothing else can see it: a dropped column in a string passes `go build`, `go vet`, `pnpm typecheck`, `pnpm db:migrate:check` and every other test, and surfaces as a member reading "Failed to load member details". Three did, after ADR-044 dropped four `id` columns — one of them on the leg that confirms a loan instalment |
| **a script under `apps/web/scripts/`** | `apps/web/test/unit/script-safety.test.ts` — end it with `runAsScript(import.meta.url, main)`, never a bare `main()`. A module that works on load cannot be safely imported, and importing is what tools, editors and checking loops do: a loop written to confirm four scripts still parsed executed `db-clear-preserve-core.mjs` and deleted every member from the production database. Destructive ones also need `requireConfirmation` and `refuseRemoteTarget` from `scripts/lib/guard.mjs` |
| **an overlay, modal or lightbox** | `apps/web/e2e/gallery-lightbox.spec.ts` — render it through a portal into `document.body` and assert a hit test lands inside it. `fixed inset-0 z-50` spans the viewport only while no ancestor opens a stacking context: the gallery lightbox was correct on `/gallery` and clipped on the home page, where the grid sits in `relative z-10` and the `fixed z-50` header painted straight over it. Check the page that wraps it, not only the page that works |
| an **upload, or a spec that causes one** | `apps/web/test/unit/script-safety.test.ts` and the guard in `uploadImage` — the test rig has a disposable **database** and no disposable **image host**. `e2e/entry-path.spec.ts` reads Cloudinary credentials out of `apps/web/.env` so it can run locally, and those name the foundation's own cloud: every local browser run left four 70-byte 1×1 pixels called `nid-front`, `nid-back`, `member-photo` and `signature` in it. `TEST_DATABASE_URL` set without `ALLOW_TEST_IMAGE_UPLOADS=yes` now refuses the upload outright |
| a **move of a stored asset** | `moveAsset`, never `uploader.rename` on its own. This account is in **dynamic folder mode**: `public_id` is the URL and `asset_folder` is the folder a human opens, and a rename moves only the first — so every admitted member's documents were served from `people/ACC-KH-33001` and still filed under `applications/APP-2026-000001`, which also made `deleteEmptyFolder` a no-op for ever. `scripts/cloudinary-reconcile.mjs` finds the drift; `test/unit/cloudinary-reconcile.test.ts` pins what it will and will not delete |
| a **streamed response** | `endStreamOnUpstreamFailure` from `lib/sse-stream.ts`. Next pipes the body *after* the handler returns, so nothing in the route can catch what it throws: an SSE connection ending for any ordinary reason became `failed to pipe response`, unhandled, in Sentry. And the producer needs a heartbeat — a stream that transmits nothing is closed by whatever is between it and the member |
| a **third-party account holding member data** | `.github/workflows/backup.yml` — it needs a job, and that job must **fail** when its credentials are absent rather than skip. The database dump covers the database; every NID scan, photograph and signature is in Cloudinary, which has no export and cannot be reconstructed from the paper passbook. A backup that passes while producing nothing is the worst outcome available to a backup |
| a screen to one staff dashboard | there is no such thing — `components/dashboard/screens/` holds one component per screen and both `app/[locale]/dashboard/{worker,admin}/` re-export it. Add it to `components/dashboard/nav.ts` with the roles that may see it |
