\section{Introduction}

\subsection{Purpose}
This document outlines the architectural design and technology stack for the Hasnahena cooperative platform. The architecture is designed to ensure:
\begin{itemize}
    \item \textbf{Scalability:} Handle growth from hundreds to thousands of members
    \item \textbf{Security:} Protect sensitive financial data and prevent unauthorized access
    \item \textbf{Compliance:} Meet regulatory and Shariah requirements
    \item \textbf{Reliability:} Ensure high availability for financial operations
\end{itemize}

\subsection{Architecture Principles}
\begin{enumerate}
    \item \textbf{Separation of Concerns:} Clear boundaries between frontend, API gateway, and core services
    \item \textbf{Defense in Depth:} Multiple security layers from WAF to application-level RBAC
    \item \textbf{Immutable Audit:} All financial actions are logged and cannot be modified
    \item \textbf{Progressive Enhancement:} Start with managed services, migrate to self-hosted as scale requires
\end{enumerate}

% ------------------------------------------------------------
% ARCHITECTURE OVERVIEW
% ------------------------------------------------------------
\section{Architecture Overview}

The system employs a \textbf{dual-microservice architecture}:
\begin{itemize}
    \item \textbf{Go (Golang) Edge Service:} Handles high-throughput traffic, real-time WebSockets, and API gateway functions
    \item \textbf{Java (Spring Boot) Core Ledger:} Handles strict double-entry bookkeeping, ACID transactions, and complex financial calculations
    \item \textbf{Next.js Frontend:} Server-side rendered React application for optimal performance and SEO
\end{itemize}

\subsection{High-Level Data Flow}
\begin{enumerate}
    \item User accesses the application via \texttt{hasnahena.org}
    \item Cloudflare WAF filters malicious traffic
    \item Request reaches Next.js frontend on Vercel
    \item API calls route through Go Edge Gateway
    \item Financial operations are delegated to Java Core Ledger
    \item Data persists to PostgreSQL with full audit logging
\end{enumerate}

\section{Scaling \& Migration Path}

\subsection{Phase 1: MVP (Free Tier)}
\begin{itemize}
    \item Vercel Hobby plan (frontend)
    \item Fly.io free tier (Go backend)
    \item Neon free tier (0.5 GB database)
    \item Cloudinary free tier (images)
    \item Estimated monthly cost: \textbf{\$0-10}
\end{itemize}

\subsection{Phase 2: Growth}
\begin{itemize}
    \item Vercel Pro (\$20/month)
    \item Fly.io scaled instances (\$15-30/month)
    \item Neon Launch plan (\$19/month)
    \item Estimated monthly cost: \textbf{\$50-100}
\end{itemize}

\subsection{Phase 3: Enterprise}
\begin{itemize}
    \item AWS EKS with auto-scaling
    \item AWS RDS Multi-AZ PostgreSQL
    \item Cloudflare Enterprise
    \item Full observability stack
    \item Estimated monthly cost: \textbf{\$300-500+}
\end{itemize}
