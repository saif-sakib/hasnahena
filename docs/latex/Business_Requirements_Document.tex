\section{Executive Summary}

Hasnahena is a community-run, interest-free cooperative finance initiative based in Bangladesh. This Business Requirements Document defines the business context, objectives, stakeholders, and acceptance criteria for the digital platform that will serve the organization's members.

The software must digitize member onboarding, deposits, withdrawals, loans, donations, and accountability while preserving Islamic finance principles (\textit{Qard al-Hasan}) and local operating practices.

\section{Business Objectives}

The Hasnahena platform aims to achieve the following primary objectives:

\begin{enumerate}
    \item \textbf{Transparent Financial Services:} Provide zero-interest financial services with complete visibility for all members.
    \item \textbf{Operational Efficiency:} Reduce manual ledger errors by digitizing request, processing, and confirmation workflows.
    \item \textbf{Risk Management:} Improve recovery and risk control through guarantor mechanisms and default-settlement rules.
    \item \textbf{Trust \& Governance:} Preserve institutional trust through immutable audit records and role-based governance.
\end{enumerate}

\section{Scope Definition}

\subsection{In Scope (Phase 1)}

\begin{itemize}
    \item Registration and approval workflow with nominee capture
    \item Core flows: Deposit, Withdrawal, Loan Application, Repayment, Donation
    \item Request $\rightarrow$ Process $\rightarrow$ Confirm lifecycle with dispute path
    \item Admin and Worker operations with strict Role-Based Access Control (RBAC)
    \item Bilingual interface (English and Bengali) for all key screens
    \item Notification triggers (SMS/email) for approvals and required actions
\end{itemize}

\subsection{Out of Scope (Phase 1)}

\begin{itemize}
    \item Mobile application release
    \item Full automatic eKYC OCR and direct government API orchestration
    \item Third-party payment gateway settlement automation
\end{itemize}

\section{Business Rules}

The following business rules govern the operation of the Hasnahena platform:

\begin{enumerate}
    \item \textbf{Minimum Deposit:} Threshold for loan eligibility is \textbf{8,000 BDT}
    \item \textbf{Withdrawal Notice:} Requires \textbf{3 months} advance notice
    \item \textbf{Zero Interest:} No interest or hidden processing fees on loans (Shariah compliance)
    \item \textbf{Donation Categories:} Pools are categorized (Operating, Lending, Zakat/Sadaqah) and used according to selected purpose
    \item \textbf{Audit Trail:} Every financial change must be auditable and non-destructive
\end{enumerate}

\section{Success Metrics}

\begin{itemize}
    \item \textbf{100\%} of monetary records traceable to a request and confirmation
    \item \textbf{Zero} unauthorized role actions in production
    \item \textbf{Reduced} manual reconciliation time compared with paper workflow
    \item \textbf{Improved} on-time installment completion after notification rollout
\end{itemize}

\section{Acceptance Criteria}

Phase 1 is accepted when all of the following conditions are met:

\begin{itemize}
    \item Core member, worker, and admin flows are operational end-to-end
    \item Audit trails, dispute flow, and settlement path are test-validated
    \item Deployment and backup procedures are documented and exercised
    \item Security review completed with no critical or high vulnerabilities
\end{itemize}

\section{Constraints \& Assumptions}

\subsection{Constraints}
\begin{itemize}
    \item Platform must comply with local cooperative/charitable regulations
    \item All financial operations must adhere to Shariah principles
    \item System must support operation in areas with limited internet connectivity
\end{itemize}

\subsection{Assumptions}
\begin{itemize}
    \item Workers and administrators have access to smartphones or computers
    \item Members have basic familiarity with mobile/web applications
    \item SMS delivery infrastructure is reliable in the operational area
\end{itemize}
