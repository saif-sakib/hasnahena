\section{Introduction}

\subsection{Purpose}
This document serves as the Software Requirements Specification (SRS) for Hasnahena, an interest-free, charitable community lending platform based on Islamic financial principles (\textit{Qard al-Hasan}).

The SRS defines the complete set of functional and non-functional requirements that the system must satisfy to meet stakeholder needs.

\subsection{Project Scope}
The Hasnahena web application provides a secure portal for community members to:
\begin{itemize}
    \item Deposit savings without earning interest
    \item Borrow funds without paying interest
    \item Act as guarantors for other members
    \item Make charitable donations (Zakat/Sadaqah)
\end{itemize}

Roles are uniquely designated into \textbf{Members}, \textbf{Workers}, and \textbf{Admins} to ensure strict financial integrity and complete access logging.

\section{Overall Description}

\subsection{Product Perspective}
The web application is built on a modern microservices architecture:
\begin{itemize}
    \item \textbf{Frontend:} Responsive Next.js (React) application with TypeScript
    \item \textbf{API Gateway:} Go-based edge service for traffic handling
    \item \textbf{Core Ledger:} Java Spring Boot service for double-entry bookkeeping
    \item \textbf{Database:} PostgreSQL with ACID transaction guarantees
\end{itemize}

\subsection{User Roles \& Permissions}

\subsubsection{Member}
The primary user of the system.
\begin{itemize}
    \item Can deposit, borrow (after meeting minimum criteria), act as guarantor, and donate
    \item All financial flows are \textbf{initiated by members}
    \item Can raise disputes for incorrect transactions
    \item Can update nominee information
\end{itemize}

\subsubsection{Worker (Staff)}
Internal staff responsible for fund processing.
\begin{itemize}
    \item Processes digital/physical fund transfers based on member requests
    \item \textbf{Cannot} delete records or initiate deposits without a request
    \item Records loan repayment installments
    \item Can record offline donations on behalf of members
\end{itemize}

\subsubsection{Admin}
Highest privilege role for system oversight.
\begin{itemize}
    \item Manages worker accounts and permissions
    \item Approves/rejects member registration and loan requests
    \item Reverses erroneous transactions (with audit logging)
    \item Configures system parameters (loan ratios, fees, minimums)
\end{itemize}

\section{Functional Requirements}

\subsection{Authentication \& Access Control}

\requirement{REQ-AUTH-01}{The system shall support login using phone number or email with password}{High}

\requirement{REQ-AUTH-02}{The system shall enforce mandatory password change on first login after approval}{High}

\requirement{REQ-AUTH-03}{The system shall implement RBAC for all protected endpoints}{Critical}

\subsection{Member Registration}

\requirement{REQ-REG-01}{The system shall allow members to create accounts with NID and nominee details}{High}

\requirement{REQ-REG-02}{The system shall queue new registrations for admin approval}{High}

\requirement{REQ-REG-03}{The system shall send notification (SMS/email) upon approval or rejection}{Medium}

\subsection{Financial Transactions}

\requirement{REQ-FIN-01}{The system shall require a minimum deposit of 8,000 BDT for loan eligibility}{High}

\requirement{REQ-FIN-02}{Workers shall process financial transactions pending final confirmation from members}{Critical}

\requirement{REQ-FIN-03}{The system shall enforce 3-month notice period for withdrawals}{High}

\requirement{REQ-FIN-04}{The system shall block withdrawals that violate loan collateral ratio}{Critical}

\subsection{Loan Management}

\requirement{REQ-LOAN-01}{The system shall calculate maximum loan based on personal cap (5× deposit), fairness cap, and solvency cap}{High}

\requirement{REQ-LOAN-02}{The system shall support guarantor request and approval workflow}{High}

\requirement{REQ-LOAN-03}{The system shall execute default settlement waterfall (borrower → guarantor → charity fund)}{Critical}

\subsection{Donations}

\requirement{REQ-DON-01}{The system shall categorize donations into Zakat, Sadaqah, and Operational Funds}{High}

\requirement{REQ-DON-02}{Donation funds shall remain isolated from withdrawable member deposits}{Critical}

\subsection{Dispute \& Audit}

\requirement{REQ-AUD-01}{The system shall provide dispute tracking if a worker processes an incorrect amount}{High}

\requirement{REQ-AUD-02}{The system shall maintain an append-only, immutable audit log for all financial actions}{Critical}

% NON-FUNCTIONAL REQUIREMENTS
% ------------------------------------------------------------
\section{Non-Functional Requirements}

\subsection{Security}
\begin{itemize}
    \item Enforce Role-Based Access Control (RBAC) on all protected resources
    \item Database transaction atomicity for all financial operations
    \item Support for multi-factor authentication (future phase)
    \item Rate limiting on authentication and sensitive endpoints
    \item All sensitive data encrypted at rest and in transit
\end{itemize}

\subsection{Compliance}
\begin{itemize}
    \item Fully Shariah-compliant (zero interest, full transparency)
    \item Robust auditing trails for regulatory compliance
    \item Data retention policies compliant with local regulations
\end{itemize}

\subsection{Usability}
\begin{itemize}
    \item Full bilingual support (English/Bengali)
    \item Responsive design for desktop and mobile browsers
    \item Accessibility compliance (WCAG 2.1 Level AA target)
\end{itemize}

\subsection{Performance}
\begin{itemize}
    \item Page load time under 3 seconds on standard connections
    \item API response time under 500ms for 95th percentile
    \item System availability target: 99.5\%
\end{itemize}

\subsection{Scalability}
\begin{itemize}
    \item Support for up to 10,000 concurrent members in Phase 1
    \item Horizontal scaling capability for backend services
\end{itemize}
