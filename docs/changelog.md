## Documentation passes

| Date | What |
|---|---|
| 2026-08-18 | **WO-62, WO-64, WO-65, WO-66 closed — no work order is open.** See batch **P** above. Four things worth keeping. (1) **A work order can specify a fix that cannot work**: WO-64 asked the support proxy to forward the member's address so the Go limiter could see past Vercel, but `TRUSTED_PROXIES` is one global number read from the trusted end, and no value of it is correct for both a direct and a proxied request — the limit moved to the Next side and [ADR-021](decisions.md) records the arithmetic so nobody retries it. (2) **The order's own numbers were wrong about the digit bias**: `% 10` over a byte makes 0–5 *4%* likelier than 6–9, not 25% — small enough that a tolerance test would have flaked rather than caught it, which is why both suites use a chi-square and keep the old implementation to prove the statistic separates them. (3) **A single click fired the handler and then submitted the form**: React swaps `type` in place when a conditional's two branches are the same component, and the `async` handler's continuation runs as a microtask *before* the browser performs the click's default action — so "Next" advanced to the Documents step and submitted it in one gesture. Proven by the regression test, which counted three alerts on arrival before the fix and none after. (4) **An `httptest` handler that does not drain the request body cannot see the client leave**, so `Server.Close` blocks and the suite hangs with no failure and no output — half an hour spent suspecting the code under test |
| 2026-08-18 | **WO-53 → WO-61 and WO-63 closed; the board has no broken requirement left.** See batch **O** above. Four things worth keeping. (1) **A correct, tested function can be defeated by the stack around it** — `clientIP` was right and unit-tested while the limiter keyed on a spoofable header, because `RealIP` had overwritten its input three middlewares earlier; the test that catches it had to drive the whole stack.
